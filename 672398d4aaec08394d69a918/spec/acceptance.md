# 验收条件

## 1. 环境

| 项 | 要求 |
| --- | --- |
| 入口 | 固定 CSR / hash 路由，刷新任意 hash 都回到同一页面 |
| 视口 | 桌面 1280×800 与移动 390×844 各跑一遍核心流程 |
| 数据 | 真实 SQLite，非内存模拟 |
| 身份 | 平台登录态；学生为房间内昵称 |

## 2. 核心流程

| # | 步骤 | 期望 |
| --- | --- | --- |
| 1 | 打开首页 | 统计条显示真实计数；三张入口卡可见 |
| 2 | 进入教师端 | 显示当前身份称呼，可改名并持久化 |
| 3 | 创建课堂：房间号 `T1L1`，字表「明 休 林 好」 | 创建成功并跳转控台；字块显示模式角标与结构说明 |
| 4 | 点「保存并开始上课」 | 状态变为进行中，当前题号为 0 |
| 5 | 学生打开 `#/play/T1L1`，昵称「小测」加入 | 看到第 1 题「明」与两个部件「日」「月」 |
| 6 | 把「日」「月」按左右摆好并提交 | 反馈卡：✓ 答对了、拼音 `míng`、`日 + 月 = 明`；2 秒后进入第 2 题 |
| 7 | 第 2 题故意摆成上下后提交 | 不通过，提示再试；尝试次数 +1 |
| 8 | 连续错到第 3 次 | 出现结构提示，并给出「4 秒后自动进入下一题」与「我还能再试试」 |
| 9 | 点求助 ✋ | 状态墙该学生变红，求助次数 +1 |
| 10 | 老师打开状态墙 | 当前题目大字与「第 1 / 4 题」；五态统计；学生格子显示昵称与答对数 |
| 11 | 老师点「结束本局并生成报告」 | 状态变为已结束，学生端显示「本局已结束」 |
| 12 | 成绩报告 | 参与人数、平均正确率、攻下字数、求助次数与逐字分布与操作一致 |
| 13 | 点「导出 CSV」 | 下载含逐字统计的 CSV，UTF-8 BOM，Excel 打开不乱码 |
| 14 | 刷新页面 | 课堂、答案、报告数据仍在 |
| 15 | 学生打开 `#/practice/T1L1` | 可练本课生字；完成后提示「已上传 N 条练习记录（不含身份信息）」 |
| 16 | 教师端「自主练习」 | 7/30/90 天指标包含刚才的练习记录 |

## 3. 判分与计分

| 用例 | 期望 |
| --- | --- |
| 「日」「月」左右摆放提交「明」 | 通过 |
| 「月」「日」左右摆放提交「明」 | 不通过（顺序错） |
| 「日」「月」上下摆放提交「明」 | 不通过（结构与左右结构不符） |
| 只放一个部件就提交 | 提交按钮禁用，文案「还差 1 块」 |
| 包围结构：内件中心落在外框内 | 通过；落在外框外 | 不通过 |
| 一次答对 | 计 15 分 |
| 第二次答对 | 计 10 分 |
| 看提示后答对 | 计 5 分 |
| 答错 | 不扣分 |

## 4. 边界与错误状态

| 场景 | 期望 |
| --- | --- |
| 打开不存在的房间号 | 「找不到游戏室」，提示确认链接 |
| 未开始就进入学生页 | 「课堂还没开始」，老师开始后自动出现题目 |
| 独体字（如「生」） | 「这个字不拆分，可以直接跳过」 |
| 学生超前作答 | 顶栏出现「预览」标记，老师切题后归位 |
| 昵称为空提交 | toast「请输入昵称」，不建记录 |
| 网络慢 | 提交按钮进入禁用态，不重复写入 |
| 数据库不可达 | 明确报错文案，不静默失败 |

## 5. 界面还原

- 设计令牌、字号、间距、圆角、阴影与 [design.md](design.md) 一致。
- 首页、学生游戏页、教师控台、档案馆、字库的布局与信息层级一致。
- 拖拽跟手、答对反馈卡 2.6 秒自动切题、倒计时条 2 秒线性收缩可用。
- 移动视口下拼字区高度降为 280 / 240，部件缩小，无横向滚动。

## 6. 数据与隔离

| 项 | 期望 |
| --- | --- |
| 刷新 / 重新打开 | 数据持久 |
| 重复执行 `seeds.sql` | 不产生重复记录 |
| 两个不同安装 | 数据互不可见 |
| 同一安装不同账号 | 共享同一份课堂数据 |
| 课后练习记录 | 不含任何身份字段 |
